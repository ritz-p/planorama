# Logical architecture components

`Graph.components` contains provider-neutral `SyntheticComponent` entities with a stable ID, kind, label and exact source-resource addresses. These entities are distinct from Terraform `Node` objects: they do not have a Terraform action, provider identity, or `ResourceRole::Container`. Original nodes remain the source of all change information. Synthetic IDs occupy a separate logical namespace and do not replace Terraform addresses.

The initial grouping rule recognizes a managed AWS `aws_lb` with one or more `aws_lb_listener` resources linked through complete, uniquely resolved `load_balancer_arn` references. `aws_lb_listener_rule` resources can join through an equally unambiguous `listener_arn` reference to an included listener. Resource type, provider, mode, visibility, uniqueness, and deposed status are checked. Literal values, partial/dynamic references, conflicting candidates, and standalone load balancers do not create groups. A rule with an ambiguous listener remains ungrouped. Membership and component order are sorted deterministically.

Target groups remain independent because they can be shared; broad ALB/NLB, API Gateway and other provider grouping rules are not inferred. The label is intentionally “Load balancer” because no subtype is inferred from values. These are logical memberships, not network containment relationships, so a component can span network boundaries without changing resource placement.

SVG diagrams append a visually distinct logical-component panel listing each member's action and Terraform address. Member links navigate to the original cards, whose metadata retains imports, drift, replacement reasons and move provenance. `data-entity-kind="synthetic"` marks component panels; `data-component-id` associates original cards with their logical entity. Synthetic entities do not increase resource/action counts or create execution/dependency edges. Ungrouped graphs render as before. See [the component example](../examples/components.svg).

This proof of concept adds an inspectable logical view while keeping source cards and edges available; it does not collapse or reroute them. The model permits future renderers to offer additional views without conflating logical grouping with spatial containment.
